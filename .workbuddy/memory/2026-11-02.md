## WebCrawler 第二阶段（采集核心引擎）已完成

新增依赖：request-pack 1.1.1（内部 axios 1.21 / cheerio 1.0.0 / iconv-lite）、playwright 1.64.1（需 `npx playwright install chromium`）、socks-proxy-agent 10.1.0、cheerio 1.0.0、linkedom 0.18.15、xpath 0.0.36、tsx 4.23.15（根 devDeps）。

关键决策与踩坑：
- request-pack 的 `createHttp().request()` 只返回 data，不返回状态码/响应头；要元数据必须用它文档化的 `instance.request()`，重试/限流由我们这层重新实现（POST 不重试）。
- request-pack 原生 proxy 只支持 http/https；SOCKS5 用 socks-proxy-agent 作为 httpAgent/httpsAgent；SOCKS4 明确报 UNSUPPORTED，不静默直连。
- **xpath 库遇到 DocumentType 节点会让整个文档 `//*` 返回空集**（linkedom 0.18.15 + xpath 0.0.36 实测）。交给 linkedom 前必须剥离 `<!doctype>`。同时用 `xpath.parse(expr).select({ node, allowAnyNamespaceForNoPrefix: true })`，否则 XHTML 命名空间导致无前缀 XPath 全失配（`xpath.select` 没有 options 入口）。
- XPath 属性轴 `//a/@href` 返回 Attr 节点，`getAttribute` 不存在，值在 `value`/`textContent` 上。
- CSS 用 cheerio、XPath 用 linkedom；跨适配器嵌套查询通过序列化子树重新解析，不做节点映射。
- SSRF 三层：协议白名单 + 请求前 DNS 全量检查 + `http.Agent({ lookup })` 连接时校验（防 rebinding）；每次重定向重新校验（axios maxRedirects=0 手动跟随）。
- 浏览器 SSRF 用 `context.route('**/*')` 拦导航请求；Browser 全局复用、Context 每次新建、信号量限制并发页。
- pipeline 的正文可能来自 `content`（type=html）而非 `html` 字段，图片与绝对地址改写要兼容两者。
- 版本统一到 0.2.0；APP_VERSION 在 apps/server/src/config.ts。

验证：pnpm build / typecheck / test 全绿（150 用例，12 文件），`pnpm --filter @webcrawler/core demo:crawl` 可跑通完整链路；H3 服务回归正常。

## WebCrawler 第五阶段（任务调度 / 代理 / 数据管理）已完成

关键设计与踩坑：
- 任务状态机放 `packages/shared/src/task-state.ts`，API / service / runtime / executor 共用一张转换表；非法转换统一 409 并在 details 给允许目标。`retryTask` 不再递增 attempts（否则执行器再 +1 就成了 2），attempts 只在执行器启动时加。
- 执行器「列表失败」不能标记栏目完成：曾因失败也写 completedCategories，重试时整栏被跳过，出现「0 成功 0 失败 → completed」的假完成。加 `categoryFailed` 标记并保留 checkpoint.page。
- `checkpoint.processedUrls` 恢复后计入 `skipped` 而不是静默跳过：原先 `seen` 用 processed 预置，恢复后 totalCount 会变小，进度条「越跑越少」。现在 seen 只统计本轮发现，processed 命中即 skipped。
- 暂停只置 `pauseRequested`（不再分发新请求，当前请求自然结束）；取消走 AbortController + `AbortSignal.any([控制信号, timeout])`。
- 重启恢复：running 一律 failed（保留断点，不猜中断副作用）；pending 需快照 + 站点 + 规则三重校验才重排；paused 保持；终态跳过。真实崩溃（Stop-Process -Force）验证：启动日志 interruptedTasks=1，任务 errorSummary「服务重启导致任务中断」。
- 定时用 croner，回调只 createTask，不在 cron 里采集；防重复三重判定（firing Set / 同 schedule / 同栏目活动任务）。PATCH 改小时靠 cron 反解重算表达式与 nextRunAt。
- 代理密码 AES-256-GCM，密钥由 PROXY_SECRET_KEY 经 scrypt 派生；无密钥写入带密码代理直接 503 CONFIGURATION_ERROR，绝不退化明文；DTO 只给 hasPassword。统计内存累加 + 5s flush（timer.unref）。
- 导出必须流式：ReadableStream + 分批 LIMIT/OFFSET + 硬上限 5000，否则一次全表会把内存打爆。CSV 带 BOM，测试里 `response.text()` 会吃掉 BOM，要读 arrayBuffer 判前三字节。
- 日志脱敏在写库前做（URL userinfo/敏感 query、detail 深度 6 层、文本 Bearer/xxx=xxx），写日志失败静默跳过。
- 测试要避开「前一个用例的后台任务仍在跑」：创建-即执行的任务会污染后续断言，用例末尾 cancel + whenIdle 再断言计数。
- vitest 断言 409 文案时注意 runtime 的 pause/cancel 曾吞异常回落到 toDto（把 409 变成 200），改前置状态检查。
- 版本统一 0.5.0；测试 33 文件 / 352 用例。端到端冒烟（真实 H3 + fixture）：建站/规则/栏目 → 任务 pending→completed 5 篇 → 增量 skipped 5 → CSV(BOM)/JSON 导出 → 代理 CRUD/脱敏/测试失败 → 日志无敏感 → 定时触发 pending + 二次 skipped → 强杀进程重启后 running→failed。

踩坑与结论（后续阶段复用）：

- **vue-tsc 遇到 `://` 会挂**：模板表达式中出现 `//`（静态属性 `placeholder="https://…"`、绑定表达式 `` `${p.type}://${p.host}` ``）会被当成注释，后续 `v-for` 作用域丢失，报「Cannot find name 'proxy'」「Property 'value' does not exist」这类完全不相干的错误。必须把带 `://` 的文案/拼接移到脚本（`lib/proxy.ts` 的 `proxyEndpoint/proxyLabel`）再绑定。
- `FormDialog` 的 `width` 是 number 类型，静态 `width="560"` 会传字符串并级联报一串模板类型错误，要用 `:width="560"`。
- Axios 封装的 `Params` 不能用 `Record<string, unknown>`：业务参数都是 interface，没有隐式索引签名，直接传会报「缺少索引签名」，改用 `object | undefined`。
- 服务端 `pageSize` 上限 100；前端写 200 会静默 400（页面看着正常但列表空），排查时先看控制台 400 的 URL。
- 任务进度计数 bug：`urls` 类型外层按 URL 个数循环、每轮又把所有 URL 当链接处理，导致同一篇算两次（total 2 / failed 4）。修法：`pageCount = target.urls.length > 0 ? 1 : pageUrls.length`。
- 插件状态误判：进程重启后注册表是空的，所有启用插件都显示「加载失败」。修法：`createApp` 启动时调 `refreshPlugins(registry)`，并加测试用「再建一个 App」模拟重启。
- 规则状态取值是 `enabled/disabled`（不是 active/inactive）；`RuleValidationDto` 字段是 `valid`（不是 ok）。
- Playwright 冒烟脚本放 `tmp/`（不入库）：逐页断言 h1、主内容非空、无 console error，再覆盖主题切换、侧栏跳转、弹窗打开、设置页脏值/撤销。

验收结果：`pnpm build` / `pnpm typecheck`（含 vue-tsc）/ `pnpm test` 全绿（36 文件 / 370 用例）；UI 冒烟 13 页 + 浅/暗两套主题 + 路由与按钮行为全部通过，截图归档 `docs/stage6-*.png`。
